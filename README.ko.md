# nmts-recovery

*[English](README.md)*

**NMTS 없이** Walrus 저장소에서 파일을 되찾는 프로그램입니다. 계정 코드와 저장해 둔 복구 목록만
있으면 됩니다.

[NMTS](https://nmts.me)는 Walrus 위에 지은 종단 간 암호화 파일 저장소입니다. 모든 파일은 올리기
전에 브라우저에서 암호화되고, 모든 열쇠는 기기를 떠나지 않는 계정 코드에서 나옵니다. 이 프로그램은
그 약속의 나머지 반입니다. NMTS가 사라져도 파일은 되찾을 수 있어야 하고, 그것을 누구의 말로도
믿어야 할 필요가 없어야 합니다.

> **이야기를 나누는 곳: [디스코드](https://discord.gg/pcmRkVmVZk).** 영어와 한국어 둘 다 읽습니다.

**어느 순간에도 NMTS 서버에 접속하지 않습니다.** 공개 Walrus 애그리게이터를, 또는 직접 받아 둔
블롭 폴더를 읽어 파일을 도로 씁니다. 자체 암호는 하나도 더하지 않습니다. 모든 열쇠 파생과 모든
복호화는 `crypto/`를 부르는 것이고, 그것은 NMTS 브라우저 코드가 WebAssembly로 컴파일하는 것과
같은 엔진입니다. 형식은 NCF-3이고, 그것을 판정하는 적합성 벡터와 함께
[nmts-crypto](https://github.com/needmoretruth/nmts-crypto)에 적혀 있습니다.

## 필요한 것

둘 중 하나:

- **복구 키트**(`nmts-recovery-kit-….txt`): 계정 코드와 복구 목록이 한 파일에 들어 있습니다. 이
  프로그램에 그 파일을 건네면 다른 것은 필요 없습니다. 그래서 그 파일을 가져가는 사람이 계정을
  가져갑니다.
- **복구 목록**(`.nmtsmap`)**과 계정 코드.** 목록은 암호화돼 있고 코드가 그것을 엽니다. 둘을 따로
  두는 것이 하나를 잃어도 살아남는 길입니다.

코드도 목록도 어디로도 보내지 않습니다. `--find`를 쓸 때는 코드에서 파생된 값이 나갑니다 —
[네트워크로 나가는 것](#네트워크로-나가는-것)을 보십시오.

## 못 하는 것

- **복구 목록 없이 파일을 찾지 못합니다.** 목록이 곧 색인입니다. 파일마다의 열쇠와 조각이 어디
  있는지를 담고 있습니다. Walrus의 블롭 주소는 내용에서 나오므로 계정 코드만으로는 아무것도 계산할
  수 없습니다. 계정이 저장 네트워크 사본을 켜 두었다면 `--find`가 계정 코드로 사본을 찾을 수 있고,
  아니면 할 수 있을 때 파일을 저장해 두십시오.
- **지운 것은 되찾지 못합니다.** NMTS에서 파일을 지우면 그 열쇠가 파기되고, 이 프로그램에 필요한
  것이 바로 그 열쇠입니다.
- **블롭이 아직 저장돼 있는지 증명하지 못합니다.** 받아 봐야 압니다.
- **2026-08-19 전에 쓴 목록은 어느 Walrus 네트워크를 가리키는지 말하지 않습니다.** 두
  애그리게이터를 다 시도하며 메인넷이 먼저입니다. 그날부터 쓴 목록은 암호화된 문서 안에 체인을
  담습니다. `--aggregator`가 전부를 덮어씁니다.
- **목록 자체가 적어 둔 저장 주소에는 접속하지 않습니다.** `--use-recorded-aggregators`로 시켜야
  합니다. 남이 건넨 키트는 그 사람이 봉한 문서이고 그 주소 목록도 그 사람 것입니다. 거기 접속하면
  그 운영자가 언제 어디서 복구했는지를 알게 됩니다. 주소는 어느 쪽이든 찍어 줍니다.
- **자기보다 새 목록은 열지 못합니다.** 목록 형식에는 버전이 있고, 오래된 빌드는 바이트를 짐작하는
  대신 멈추고 말합니다. `nmts-recovery --version`이 읽을 수 있는 가장 새 목록 버전을 찍습니다.

## 받기

`nmts` 명령줄 도구가 이 기계에 맞는 릴리스를 받아 릴리스의 체크섬 파일과 대조합니다:
`nmts recovery --out ~/tools`. 또는 Rust 1.75 이상으로 직접 빌드하십시오. 다른 도구는 필요
없습니다.

```sh
cd recovery
cargo build --release     # recovery/target/release/nmts-recovery (윈도우는 .exe)
cargo test                # 합성한 저장소에서 실제 파일을 되찾습니다. 네트워크 없음
```

리눅스, macOS, 윈도우에서 그대로 돕니다.

## 터미널에서 쓰기

```sh
nmts-recovery --map ~/Downloads/nmts-recovery-map.nmtsmap --out ~/recovered
```

계정 코드를 묻고, 복구 목록이 무엇을 담고 있는지 보여 준 뒤, 파일마다 받고 복호화하고 검증하고
씁니다. 무엇이든 하기 전에:

```sh
nmts-recovery --map FILE --list               # 목록이 담은 것. 네트워크 없음, 쓰는 것 없음.
nmts-recovery --map FILE --print-fetch-plan   # 정확한 URL을 curl 명령으로
```

이 프로그램이 네트워크 연결을 아예 열지 않기를 바라면, `--print-fetch-plan`이 찍은 명령으로
블롭을 직접 받아 그 폴더를 `--blobs-dir`로 넘기십시오. 바이트가 도착한 뒤는 똑같습니다.

| 옵션 | |
|---|---|
| `--map FILE` | 복구 목록(`.nmtsmap`) **또는** 복구 키트(`.txt`). `--find`·`--gui`·`--derive`가 아니면 필수. |
| `--find` | 계정 코드만으로 Walrus에서 목록을 찾습니다. 아래 참고. |
| `--rpc URL` | `--find`가 물을 Sui 노드. 반복 가능, 순서대로 시도. |
| `--owner 0xADDRESS` | `--find`와 함께, 업로드 값을 낸 지갑. 그 지갑이 브라우저 확장이나 가져온 열쇠일 때만 필요. |
| `--out DIR` | 되찾은 파일을 쓸 곳. 되찾을 때 필수. |
| `--code-file FILE` | 계정 코드를 치는 대신 파일에서 읽습니다. |
| `--aggregator URL` | 읽을 Walrus 애그리게이터. 반복 가능, 순서대로 시도. |
| `--use-recorded-aggregators` | 목록 안에 적힌 저장 주소에서도 읽습니다. 기본은 끔. |
| `--blobs-dir DIR` | 네트워크 대신 디렉터리에서 블롭을 읽습니다. |
| `--only TEXT` | 경로나 이름에 TEXT가 든 파일만 되찾습니다. |
| `--overwrite` | 이미 있는 파일을 바꿉니다. 기본은 끔. |
| `--derive` | 계정 코드가 파생하는 것을 찍고 멈춥니다. 목록 없음, 네트워크 없음. |
| `--wallets N` | `--derive`가 걷고 `--find`가 찾아볼 지갑 수. 기본 1. |
| `--secrets` | `--derive`와 함께, 지갑 개인 키도 찍습니다. |
| `--lang en\|ko` | 메시지 언어. 기본 영어. 자동 감지는 없습니다. |

**계정 코드는 절대 인자가 아닙니다.** 프로그램이 물을 때 치거나 `--code-file`에서 읽습니다. 인자로
주면 셸 기록에 남고 다른 사용자에게 보입니다.

## 목록 파일이 없을 때

계정이 저장 네트워크 사본을 켜 두었다면 복구 목록의 사본이 Walrus에 있고, 계정 코드만으로 찾을 수
있습니다.

```sh
nmts-recovery --find --out ~/recovered
```

계정 코드에서 예측할 수 있는 것이 둘 있습니다. 저장 값을 낸 지갑과, 목록이 저장된 이름. 그래서
주소를 파생하고, 공개 Sui 노드에 그 지갑이 어떤 블롭 객체를 가졌는지 묻고, 애그리게이터에 그 이름의
패치를 청하고, 돌아온 것을 엽니다. Sui 노드는 누군가 그 주소에 관심이 있다는 것을, 애그리게이터는
누군가 그 패치를 청했다는 것을 알게 됩니다. 어느 쪽에도 계정 코드는 주지 않습니다.

업로드 값을 브라우저 확장이나 가져온 지갑으로 냈다면 `--owner 0xADDRESS`를, 첫 파생 지갑 밖의 지갑을
썼다면 `--wallets N`을 주십시오. 아무것도 못 찾는 것도 답이며, 평범한 이유가 셋 있습니다. 사본을
켠 적이 없거나, 값을 낸 지갑이 이 코드가 파생하는 것이 아니거나, 계정이 큰 파일만 올렸거나 — 큰
파일은 목록을 싣는 퀼트 안이 아니라 제 블롭으로 저장됩니다. 그때는 `.nmtsmap` 파일을 쓰십시오.

## 터미널 대신 브라우저에서 쓰기

```sh
nmts-recovery --gui
```

주소를 찍고, 열 수 있으면 열고, 조작 화면을 내줍니다. 복구 목록을 고르고, 무엇이 들었는지 보고,
원하는 것에 표시하고, 어디로 갈지 말하고, 되는 것을 지켜봅니다. 화면은 목록을 그리고 어느 줄에
표시했는지를 돌려보낼 뿐입니다. 모든 열쇠, 모든 받기, 모든 복호화, 모든 파일 쓰기는 Rust 실행
파일 안에서 일어납니다. 브라우저는 열쇠를 갖지 않고 아무것도 쓰지 않습니다.

**계정 코드는 터미널에 칩니다. 브라우저에는 절대 넣지 않습니다.** 브라우저는 개인 기계에서 가장
넓은 공격면입니다. 확장은 페이지 내용을 읽고, 비밀번호 관리자는 자격처럼 보이는 것을 기억하려 하고,
폼 값은 탭보다 오래 삽니다. 그래서 프로그램은 자신을 띄운 터미널에서 코드를 묻고, 화면은 거기를
보라고 말합니다. 화면은 복구 목록이 아닌 파일은 읽기를 거절하며, 그것이 **키트**(목록과 코드가 한
파일)를 브라우저 밖에 두는 방법입니다. 키트만 저장해 두었다면 화면이 대신 터미널 명령을 줍니다.
조작 채널의 어떤 경로도 계정 코드를 받지 않고, 시험이 그것을 확인합니다.

내 기계에서 띄운 화면을 믿을 수 있는 이유:

1. 리스너는 `127.0.0.1`에 묶여 있습니다.
2. 실행마다 새 32바이트 토큰을 만들어 터미널에 한 번 찍고, 모든 요청은 그것을 싣거나 거절됩니다.
   메모리에만 있습니다.
3. `Host` 헤더는 루프백 주소와 포트여야 합니다. 그것이 DNS 리바인딩을 막습니다.
4. 어떤 응답도 교차 출처 헤더를 싣지 않고, 다른 `Origin`은 거절합니다.
5. 데스크톱에는 주소가 아니라 파일을 건넵니다. 토큰은 비밀이고, 명령줄의 주소는 그 기계의 모든
   계정에 보이기 때문입니다. 그 파일은 소유자만 읽을 수 있고, 브라우저를 그 주소로 보내는 일만 하며,
   곧 지워집니다. 쓸 수 없으면 아무것도 열지 않고 주소는 터미널에 남습니다.

각각을 제 시험이 지킵니다. 화면은 `recovery/gui/index.html` 한 파일이고, 라이브러리도 없고 어디서도
불러오지 않습니다. `--write-gui FILE`이 사본을 써 주어 읽어 볼 수 있습니다. 그 사본을 그냥 열면
일부러 아무것도 하지 않습니다.

## 지갑도 되찾기

계정의 모든 열쇠는 계정 코드에서 계산되며, 저장 값을 내는 지갑도 그렇습니다. 그 계산은 다른 무엇도
대신하지 못합니다.

```sh
nmts-recovery --derive              # 계정 id, 지문, 공개 코드, 지갑 주소
nmts-recovery --derive --secrets    # 같은 것에 더해 지갑 개인 키. 경고 뒤에
```

파생은 NMTS 자신이 쓰는 라이브러리에서 뽑은 고정값과 대조합니다(`recovery/src/derive.rs`).

## 네트워크로 나가는 것

**계정 코드는 절대 나가지 않습니다.** 열쇠는 그 자리에서 파생되고 코드는 어떤 요청에도 실리지
않습니다. 나가는 것은 이것입니다.

```
GET https://<aggregator>/v1/blobs/<blob id>                       --blobs-dir가 아닌 모든 복구
GET https://<aggregator>/v1/blobs/by-quilt-patch-id/<patch id>
POST https://<sui node>/     파생한 지갑에 대한 suix_getOwnedObjects     --find만
GET https://<aggregator>/v1/blobs/by-quilt-patch-id/<derived patch id>      --find만
```

공개 블롭을 공개 id로 받으며, 모든 응답은 목록이 적은 암호문 길이로 제한됩니다. `--find`의 두
요청은 계정 코드에서 파생되므로, 누군가 이 계정의 파일을 지금 이 주소에서 찾고 있다는 것을 남의
서버에 알립니다. 코드 자체는 보내지 않고 되짚을 수도 없습니다. `--rpc`로 내 노드를 대고,
`--map FILE`은 조회 자체를 피합니다. 목록 안에 적힌 주소는 `--use-recorded-aggregators`로 시키지
않는 한 접속하지 않습니다.

## 파일이 돌아왔다고 말하기 전에 무엇을 확인하는가

- **자리는 위치로 확인합니다.** 조각의 봉인된 머리가 말하는 자리를 쓰려는 자리와 대조합니다. 조각
  자신의 기록으로는 하지 않습니다.
- **길이는 두 번 확인합니다.** 목록과 조각의 봉인된 머리에 대고. 채움이 붙은 조각(저장 크기가 파일
  크기를 드러내지 않도록 실제보다 크게 봉인한 것)은 통째로 인증하고 파일의 바이트만 쓰고 해시합니다.
- **복호화 전에 열쇠를 확인합니다.** 봉투의 열쇠 약정으로.
- **파일 전체를 해시해 목록의 해시와 비교합니다.** 조각을 가로지르는 유일한 확인입니다.
- **반쯤 쓰인 것을 끝난 것처럼 남기지 않습니다.** 파일마다 임시 이름으로 쓰고 모든 확인이 지난 뒤
  이름을 바꿉니다.
- **실패는 파일 하나의 값이지 복구 전체의 값이 아닙니다.** 무엇이 실패했는지 이름을 대고, 종료
  코드가 그렇다고 말합니다.
- **파일의 날짜를 되돌려 놓습니다.** 목록이 날짜를 적었을 때, 파일이 다 된 뒤에. 날짜가 없는 목록은
  파일을 복구한 시각으로 둡니다.

프로그램이 판단에 쓰지 않는 것: 목록의 날짜, `totals`, 그리고 `.nmtsmap` 파일의 평문 머리 — 파일을
가진 누구나 고칠 수 있는 곳입니다. 그 머리의 어떤 URL도 소프트웨어를 받을 곳으로 찍지 않습니다.

종료 코드: `0` 전부 되찾음 · `1` 시작하지 못함 · `2` 인자가 틀림 · `3` 실패한 파일이 있음.

## 문제 알리기

이슈를 열거나 nmts@nmts.me로 쓰십시오. **계정 코드를 넣지 마십시오** — 버그 보고에도, 이슈에도,
