# nmts-recovery

*[English](README.md)*

계정 코드와 미리 저장해 두신 복구 목록 파일만으로, **NMTS 없이** 월러스 저장소에서 파일을 되찾는
프로그램입니다.

**NMTS**([nmts.me](https://nmts.me))는 월러스 위에 만든 종단 간 암호화 파일 저장소입니다. 모든
파일은 업로드되기 전에 브라우저에서 암호화되고, 모든 열쇠는 기기 밖으로 나가지 않는 계정 코드에서
나옵니다. 이 프로그램은 그 약속의 나머지 절반입니다 — NMTS가 사라져도 파일은 되찾을 수 있어야
하고, 그것을 누구의 말만 믿고 받아들이실 필요는 없어야 합니다.

> **이야기를 나누는 곳: [디스코드](https://discord.gg/pcmRkVmVZk).** 질문도, 의견도, 무엇을
> 만들고 계신지도. 영어와 한국어 둘 다 읽습니다.

**NMTS 서버에는 한 번도 접속하지 않습니다.** 공개 월러스 애그리게이터에서 읽거나, 직접 받아 두신
블롭 폴더에서 읽어 파일을 되돌려 놓습니다.

* 라이선스: **Apache-2.0**(`LICENSE`). 2026년 8월 30일에 AGPL-3.0-only에서 옮겼고, 그전에 받아
  두신 사본은 그대로 AGPL로 남습니다. 다른 조건이 필요하시면 **nmts@nmts.me** 로 이유와 함께
  알려 주십시오. Copyright © 2026 needmoretruth.
* **자체 암호를 새로 짜지 않았습니다.** 열쇠 유도도, 봉투도, 스트림 복호화도 전부 `crypto/`를
  부르는 것이고, 그것은 NMTS 브라우저 코드가 WebAssembly로 컴파일하는 바로 그 엔진입니다. 형식은
  NCF-3이고 [nmts-crypto](https://github.com/needmoretruth/nmts-crypto)에 적합성 벡터와 함께
  문서로 있습니다.

## 필요한 것

둘 중 하나면 됩니다.

* **복구 키트**(`nmts-recovery-kit-….txt`) — 계정 코드와 복구 목록이 **한 파일 안에** 다 들어
  있습니다. 이 파일만 주시면 더 필요한 것이 없습니다.
  ⛔ 그래서 이 파일을 가져가는 사람은 계정을 통째로 가져갑니다.
* **복구 목록**(`.nmtsmap`)**과 계정 코드.** 목록은 암호화돼 있고 코드가 그것을 엽니다. 둘을 따로
  두시면 하나를 잃어도 살아남습니다.

코드도 목록도 어디로도 보내지 않습니다. `--find`를 쓰실 때는 코드에서 **유도된 값**이 나갑니다 —
아래 **네트워크로 나가는 것**을 봐 주십시오.

## 못 하는 것

복구 도구가 자기를 부풀려 말하면 없느니만 못하므로, 그대로 적습니다.

* **복구 목록 없이는 파일을 못 찾습니다.** 목록이 색인입니다 — 파일마다의 열쇠와 조각이 어디
  있는지가 거기 있습니다. 월러스의 블롭 주소는 내용에서 나오므로 계정 코드만으로 계산되지
  않습니다. 목록이 있을 수 있는 곳은 둘입니다: 저장해 두신 `.nmtsmap` 파일, 그리고 계정에서
  「복구 목록을 저장망에도 둡니다」를 켜 두었다면 계정 코드로 찾아낼 수 있는 월러스 위의 사본
  (`--find` · 아래 참고). 둘 다 없으면 여기서 새로 만들어 낼 방법은 없으니, 지금 파일을 저장해
  두십시오.
* **지우신 것은 되찾지 못합니다.** NMTS에서 파일을 지우면 그 열쇠가 없어지고, 이 프로그램이
  필요로 하는 것이 그 열쇠입니다.
* **블롭이 아직 저장돼 있는지 증명하지 못합니다.** 가져와 봐야 압니다.
* **2026년 8월 19일 이전에 쓰인 목록은 어느 월러스 망인지 말하지 않습니다.** 저장망을 이름
  (`walrus`)으로만 적고, 메인넷과 테스트넷의 블롭 식별자는 생김새가 같아서 양쪽 애그리게이터를
  다 시도합니다(메인넷 먼저). 그날 이후에 쓰인 목록은 암호화된 문서 안에 체인을 담고 있어 맞는
  쪽을 먼저 묻습니다. 다른 쪽도 여전히 시도하므로, 체인을 잘못 적은 목록이 치르는 값은 복구
  실패가 아니라 요청 한 번입니다. `--aggregator`가 이 전부를 덮어씁니다.
* **목록 자신이 적어 둔 저장 주소로는 접속하지 않습니다.** 목록에는 그것이 쓰일 때 브라우저가
  읽고 있던 애그리게이터가 기록돼 있을 수 있습니다. `--use-recorded-aggregators`로 요청하시기
  전에는 접속하지 않습니다: 목록은 암호화돼 있지만 **복구 키트는 계정 코드를 담고 있으므로**,
  남이 건네준 키트는 그 사람이 만든 문서이고 그 안의 모든 칸이 그 사람의 것입니다 — 그 주소
  목록도 포함해서. 그런 주소에 접속하면 그 운영자에게 「어느 주소에서 언제 복구했는지」를 알려
  주게 되고, 돌아온 바이트를 인증한다고 해서 이미 나간 요청이 없던 일이 되지는 않습니다. 주소는
  어느 쪽이든 화면에 찍히므로, 내장된 주소가 죽는 날을 위해 거기 있습니다.
* **옛 사본은 새 목록을 못 엽니다.** 목록 형식에는 버전이 있고, 그보다 옛 빌드는 모르는 바이트를
  짐작하지 않고 멈추고 그렇게 말합니다 — 짐작이야말로 「맞아 보이지만 아닌 파일」을 만들어 내는
  길입니다. `nmts-recovery --version`은 프로그램 자신의 번호와 읽을 수 있는 가장 새 목록 버전을
  함께 찍습니다. 목록이 그보다 앞서 있으면 이 저장소에서 새 빌드를 받으십시오.

## 빌드

Rust 1.75 이상. 다른 도구도, 빌드 스크립트도, 코드 생성도 없습니다.

```sh
cd recovery
cargo build --release
```

실행 파일은 `recovery/target/release/nmts-recovery`에 생깁니다(윈도우에서는
`nmts-recovery.exe`). 리눅스·맥·윈도우에서 네이티브로 돌고, 호환 계층은 필요 없습니다.

시험을 돌려 보십시오 — 네트워크 없이, 합성한 저장소에서 진짜 파일을 되살립니다.

```sh
cd recovery
cargo test
```

## 터미널에서 쓰기

```sh
nmts-recovery --map ~/Downloads/nmts-recovery-map.nmtsmap --out ~/recovered
```

계정 코드를 묻고, 복구 목록이 무엇을 담고 있는지 보여 준 뒤, 파일마다 가져와서 복호화하고
확인하고 씁니다.

무엇이든 시작하시기 전에 쓸 만한 것:

```sh
nmts-recovery --map FILE --list               # 복구 목록에 무엇이 있는가. 네트워크도, 쓰기도 없음.
nmts-recovery --map FILE --print-fetch-plan   # 정확한 주소를, curl 명령 모양으로
```

이 프로그램이 네트워크에 아예 접속하지 않기를 바라신다면 `--print-fetch-plan`으로 나온 명령으로
블롭을 직접 받으신 뒤, 그 폴더를 `--blobs-dir`로 주십시오. 바이트가 도착한 뒤부터는 어느 쪽이든
완전히 같습니다.

| 옵션 | |
|---|---|
| `--map FILE` | 복구 목록(`.nmtsmap`) **또는** 목록이 안에 든 복구 키트(`.txt`). `--find`·`--gui`·`--derive`가 아니면 필수. |
| `--find` | 저장한 파일 없이, 계정 코드만으로 월러스에서 목록을 찾습니다. 아래 참고. |
| `--rpc URL` | `--find`가 물어볼 Sui 노드. 여러 번 줄 수 있고 준 순서대로 시도합니다. |
| `--owner 0xADDRESS` | `--find`와 함께 — 업로드 값을 낸 지갑. 그 지갑이 확장 프로그램 지갑이거나 가져온 개인 키일 때만 필요합니다(계정 코드로는 그런 주소가 유도되지 않습니다). |
| `--out DIR` | 되찾은 파일을 쓸 곳. 복구할 때는 필수. |
| `--code-file FILE` | 계정 코드를 입력하는 대신 파일에서 읽습니다. |
| `--aggregator URL` | 읽어 올 월러스 애그리게이터. 여러 번 줄 수 있고 준 순서대로 시도합니다. |
| `--use-recorded-aggregators` | 복구 목록 안에 적힌 저장 주소에서도 읽습니다. 기본은 꺼짐 — 아래 참고. |
| `--blobs-dir DIR` | 네트워크 대신 폴더에서 블롭을 읽습니다. |
| `--only TEXT` | 경로나 이름에 TEXT가 들어간 파일만 복구합니다. |
| `--overwrite` | 이미 있는 파일을 덮어씁니다. 기본은 꺼짐. |
| `--derive` | 계정 코드에서 무엇이 나오는지 찍고 끝냅니다. 목록도, 네트워크도 필요 없습니다. |
| `--wallets N` | `--derive`가 훑을 지갑 수, `--find`가 뒤져 볼 지갑 수. 기본값 1. |
| `--secrets` | `--derive`와 함께 — 지갑 개인 키까지 찍습니다. |
| `--lang en\|ko` | 메시지 언어. 기본은 영어이고, 자동으로 알아내지 않습니다. |

## 목록 파일이 없을 때

계정에서 「복구 목록을 저장망에도 둡니다」를 켜 두었다면 복구 목록의 사본이 월러스에 있고, 계정
코드만으로 찾을 수 있습니다.

```sh
nmts-recovery --find --out ~/recovered
```

월러스의 블롭 식별자는 그 블롭 바이트의 해시라서 계정 코드로 예측되지 않습니다. 다만 예측되는
것이 둘 있고, 그 둘이면 충분합니다: 저장 값을 낸 지갑이 계정 코드에서 나오고, 목록이 저장된
이름도 계정 코드에서 나옵니다. 그래서 주소를 유도하고, 공개 Sui 노드에 그 지갑이 가진 블롭
객체를 묻고, 애그리게이터에 그 이름의 패치를 하나씩 묻고, 돌아온 것을 같은 코드로 엽니다.

⚠ **그 조회가 남에게 알려 주는 것.** Sui 노드는 「누군가 그 주소에 관심이 있다」를 알게 되고,
애그리게이터는 「누군가 그 패치들을 달라고 했다」를 알게 됩니다. 둘 다 공개 서비스에 공개 질문을
하는 것입니다. 어느 쪽에도 계정 코드는 주지 않으며, 그것은 이 프로그램 밖으로 나가지 않습니다.

가끔 알려 줘야 하는 것이 둘 있습니다. 업로드 값을 확장 프로그램 지갑이나 가져온 개인 키로
내셨다면 `--owner 0xADDRESS`(계정 코드로는 그런 주소가 안 나옵니다), 그리고 계정이 첫 번째로
유도된 지갑 말고 다른 것도 썼다면 `--wallets N`입니다.

아무것도 못 찾는 것은 실패가 아니라 답이고, 평범한 이유가 셋 있습니다: 그 설정을 켠 적이 없거나,
값을 낸 지갑이 이 코드에서 유도되는 것이 아니거나, 그 계정이 큰 파일만 업로드했거나. 큰 파일은
퀼트 안이 아니라 자기 블롭으로 저장되는데, 목록을 싣고 다니는 것은 퀼트입니다. 어느 경우든
`.nmtsmap` 파일을 쓰십시오.

## 터미널 대신 브라우저에서 쓰기

400개 중 8개를 고르는 일을 터미널에서 하고 싶지 않으시다면:

```sh
nmts-recovery --gui
```

주소를 찍고, 열 수 있으면 열어 주고, 조작 화면을 띄웁니다. 복구 목록이나 키트를 고르고, 무엇이
들었는지 보고, 원하는 것에 표시하고, 어디에 쓸지 정하고, 되는 것을 보시면 됩니다.

**일은 여전히 프로그램이 합니다.** 화면은 목록을 그리고 어느 줄에 표시하셨는지를 돌려보낼
뿐입니다. 모든 열쇠, 모든 가져오기, 모든 복호화, 모든 파일 쓰기는 Rust 실행 파일 안에서
일어납니다. 브라우저는 열쇠를 갖지 않고, 블롭을 열지 않고, 아무것도 쓰지 않습니다.

### 계정 코드는 터미널에 입력하십니다 — 브라우저에는 절대 넣지 않습니다

일부러 그렇게 했고, 나머지 설계가 여기서 나옵니다. 브라우저는 개인 기계에서 공격 면이 가장 넓은
곳입니다 — 확장 프로그램은 어느 페이지의 내용이든 읽을 수 있고, 비밀번호 관리자는 자격처럼
생긴 것을 기억해 두겠다고 나서며, 입력값은 탭보다 오래 남습니다. 계정 코드는 그 계정의 마스터
열쇠이고 다른 모든 열쇠가 거기서 나옵니다. 그래서 화면이 목록 파일을 넘기고 나면, 프로그램은
자기가 시작된 터미널 창에서 코드를 묻고, 화면은 그쪽을 보시라고 말합니다.

화면은 복구 목록이 아닌 파일은 **읽지도 않습니다**. 목록은 JSON 문서이므로 화면이 앞의 몇
바이트만 보고 아니면 거기서 멈춥니다. 이 검사가 있는 이유는 **복구 키트** 때문입니다 — 목록과
계정 코드가 함께 든 한 파일 형태 말입니다. 그것을 화면의 파일 고르개에서 고르면 브라우저가
통째로 읽어 들이게 됩니다. 키트만 저장해 두셨다면 화면이 그렇게 말하고 명령을 알려 드립니다:
`nmts-recovery --map <그 파일>`. 키트가 코드를 이미 갖고 있으므로 아무것도 묻지 않습니다.

제어 통로의 어떤 길도 계정 코드를 받지 않으며, 시험이 그것을 지킵니다 — 파일 글을 받는 길에
**진짜 키트를 넣어 보는** 시험까지 포함해서. 코드가 실제로 도착할 수 있었던 길이 그것이기
때문입니다.

### 내 기계에서 띄운 화면을 왜 믿을 수 있는가

다섯 가지이고, 어느 하나만으로는 충분하지 않습니다.

1. 듣는 자리가 `127.0.0.1`에 묶여 있습니다. 기계 밖에서는 아무것도 접속하지 못합니다.
2. 실행마다 새 32바이트 토큰을 만들어 터미널에 한 번 찍습니다. 모든 요청이 그것을 지녀야 하고
   아니면 거절됩니다. 그것은 메모리에만 있고 프로세스와 함께 사라집니다.
3. `Host` 헤더가 반드시 그 루프백 주소와 포트여야 합니다. DNS 리바인딩을 막는 것이 이것입니다 —
   `127.0.0.1`로 풀리는 호스트 이름을 쓰면 인터넷 위의 페이지가 로컬 포트에 닿을 수 있고, 소켓은
   진짜로 로컬이므로 토큰만으로는 그 차이를 모릅니다.
4. 어떤 응답에도 교차 출처 헤더가 붙지 않고, 서버 자신이 아닌 `Origin`은 그 자리에서 거절됩니다.
5. 데스크톱에는 주소가 아니라 **파일**을 건넵니다. 주소를 직접 여는 것은 토큰을 명령줄에 두는
   일이고, 리눅스에서는 그 기계의 모든 계정이 명령줄을 읽을 수 있습니다. 토큰을 가진 사람은 이
   프로그램에 파일 색인 전부를 물을 수 있고 복호화된 파일을 어디에 쓸지도 정할 수 있으므로,
   그것은 주소 자체와 같은 등급의 비밀입니다. 그 파일은 주인만 읽을 수 있는 권한과 짐작 못 할
   이름으로 만들어지고, 브라우저를 그 주소로 보내는 것 말고는 아무 일도 하지 않으며, 곧 지워
   집니다. 그것을 못 쓰면 아무것도 열지 않습니다 — 주소는 어느 쪽이든 터미널에 있고, 조용히
   물러서는 것은 하필 「주인만 읽는 파일을 못 쓰는 시스템」에서 토큰을 프로세스 목록에 올리는
   일이기 때문입니다.

다섯 가지 모두 각자의 시험이 지키고 있고, 그 시험들은 검사를 빼 보고 실패하는 것을 확인한
것들입니다.

화면은 `recovery/gui/index.html` 한 파일이고, 라이브러리도 없고 어디서 불러오는 것도 없습니다.
`nmts-recovery --write-gui FILE`로 사본을 꺼내 읽어 보실 수 있습니다. 그 사본을 그냥 열면 아무
일도 일어나지 않는데, 일부러 그렇습니다 — `file://`로 열린 페이지는 프로그램이 다른 `file://`
페이지와 구별할 수 있는 출처가 없어서, 그것을 들여보내는 것은 그 전부를 들여보내는 일입니다.

## 지갑도 되찾기

계정 코드는 비밀번호가 아니라 **뿌리**입니다. 그 계정의 모든 열쇠가 거기서 계산되고, 저장 값을
내는 지갑도 그렇습니다. 「파일을 되찾는다」는 필요한 것의 절반이고, 나머지 절반은 「지갑을
되찾는다」인데 그 계산을 대신해 줄 수 있는 것이 달리 없습니다.

```sh
nmts-recovery --derive              # 계정 식별자, 지문, 공개 코드, 지갑 주소
nmts-recovery --derive --secrets    # 위의 것에 더해 지갑 개인 키까지
```

`--derive`는 공개된 쪽을 찍습니다. `--secrets`는 경고 뒤에 개인 키를 더합니다 — 어느 계정의
코드인지 확인해 보려던 분의 터미널 기록에 쓸 수 있는 열쇠가 딸려 남으면 안 되기 때문입니다.

지갑 유도는 NMTS 자신이 쓰는 라이브러리에서 가져온 기준값과 대조합니다(`recovery/src/derive.rs`).
이 프로그램과 브라우저가 주소에 대해 서로 다르게 말한 적이 있었다면, 누군가는 엉뚱한 지갑에
돈을 넣었을 것입니다.

## 네트워크로 나가는 것

**계정 코드는 나가지 않습니다.** 읽어서 그 자리에서 열쇠를 유도할 뿐이고, 이 프로그램이 만드는
어떤 요청에도 들어가지 않습니다. 아래가 **나가는 것 전부**입니다.

`--blobs-dir`를 쓰지 않는 모든 복구에서, 바이트를 가져오는 요청:

```
GET https://<애그리게이터>/v1/blobs/<블롭 식별자>
GET https://<애그리게이터>/v1/blobs/by-quilt-patch-id/<패치 식별자>
```

공개된 블롭을, 그 공개된 식별자로. 무엇을 가져오기 전에 목록을 먼저 열고, 모든 응답은 복구
목록이 말하는 정확한 암호문 길이로 미리 한계를 걸고 읽습니다.

`--find`를 쓰면 둘이 더 있습니다. 식별자를 읽어 낼 저장된 파일이 없기 때문입니다.

```
POST https://<Sui 노드>/           유도된 지갑 주소에 대한 suix_getOwnedObjects
GET  https://<애그리게이터>/v1/blobs/by-quilt-patch-id/<유도된 패치 식별자>
```

⚠ **그 둘은 계정 코드에서 유도된 값입니다.** 그러므로 그것을 묻는 것은 남의 서버에 「누군가 이
계정의 파일을, 이 주소에서, 지금 찾고 있다」고 말하는 일입니다. 코드 자체는 보내지 않고 어느
서버도 거기서 코드를 되짚어 낼 수 없습니다 — 다만 그 질문들이 익명은 아닙니다. `--rpc`로 직접
운영하시는 노드를 지정하실 수 있고, `--map FILE`을 쓰면 그 조회 자체가 없습니다.

접속하는 주소는 이 프로그램에 내장된 것들입니다. 복구 목록이 자기 저장 주소를 적어 둘 수 있지만,
`--use-recorded-aggregators`로 요청하시기 전에는 **접속하지 않습니다.**

## 파일이 돌아왔다고 말하기 전에 무엇을 확인하는가

절반만 되고 성공했다고 말하는 복구야말로 막아야 할 실패이므로:

* **자리는 자리로 확인합니다.** 조각마다 암호화된 헤더가 자기가 몇 번째 자리의 것인지 말하고,
  그것을 지금 쓰고 있는 자리와 대조합니다 — 조각 자신의 기록과 대조하지 않고, 조각들을 자기가
  주장하는 번호로 정렬한 뒤에 대조하지도 않습니다.
* **길이는 서로 다른 두 권위에 대고 두 번 확인합니다**: 복구 목록이 말하는 값과, 조각 자신의
  암호화된 헤더가 말하는 값. 한 바이트를 쓰기 전에 둘이 일치해야 합니다. 조각은 **자릿수가 채워져**
  있을 수 있습니다 — 저장된 크기로 파일 크기를 알 수 없게 하려고 담긴 바이트보다 크게 암호화된
  경우인데, 그때는 목록이 두 숫자를 다 갖고 있고, 채운 부분도 다른 것과 똑같이 복호화·인증되며,
  파일 자신의 바이트만 쓰이고 해시됩니다.
* **복호화를 시작하기 전에 열쇠가 그 파일 것인지 확인합니다** — 봉투의 열쇠 확약값으로.
* **파일 전체를 해시해서** 복구 목록이 적어 둔 해시와 비교합니다. 조각을 가로지르는 검사는 이것
  하나뿐이므로, 조각 하나하나는 완벽한데 모아 놓으면 엉뚱한 파일인 경우를 잡는 것도 이것뿐입니다.
* **반쯤 쓰인 것이 다 된 것처럼 남지 않습니다.** 파일은 목적지 폴더 안에서 임시 이름으로 쓰이고,
  위의 모든 검사를 지난 뒤에야 제 이름을 얻습니다.
* **하나가 실패해도 값은 파일 하나입니다.** 무엇이 실패했는지 이름을 대고, 종료 코드가 무언가
  실패했다고 말합니다.
* **파일의 원래 날짜를 되돌려 놓습니다** — 목록이 날짜를 기록해 두었을 때, 파일이 완성돼 제자리에
  놓인 뒤에. 절대 그 전이 아니고, 시각을 거부하는 파일 시스템이 치르는 값은 파일이 아니라 한 줄의
  알림입니다. 날짜를 기록하지 않은 목록은 파일을 복구한 시각으로 둡니다 — 그것이 정직합니다.
  1970년 1월 1일로 찍는 것은 고장으로 읽힐 것입니다.

⚠ **판단에 쓰지 않는 것**: 목록의 날짜들, `totals`, 그리고 `.nmtsmap` 파일의 평문 헤더에 있는
모든 것. 날짜는 저장 계층에서 온 것이고 아무것에도 대조되지 않으므로, 파일에 찍기만 하고 다른
무엇에도 쓰지 않습니다. 읽은 것과 어긋나는 `totals`는 알리기만 하고 복구는 계속됩니다. 평문
헤더는 파일을 가진 사람이면 누구나 고칠 수 있으므로, 그 안의 어떤 것도 조언으로 보여 주지 않고
그 안의 어떤 주소도 「소프트웨어를 받는 곳」으로 찍지 않습니다 — 목록에 대해 프로그램이 보여
주는 것은 암호화된 문서에서 나옵니다.

종료 코드: `0` 전부 복구됨 · `1` 시작하지 못함 · `2` 인자가 잘못됨 · `3` 실패를 안고 끝남.
